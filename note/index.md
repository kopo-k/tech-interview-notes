SQLのINDEXというのは本の巻末索引と同じような役割を持つものです。
INDEXを挿入いたしますと、データを読み取る速度が上がりますが、逆に書く作業(INSERT,UPDATE,DELETE)は遅くなってしまうので、必要な箇所のみINDEXを挿入することが重要です

遅くなる原因と致しましては、テーブル本体のデータとINDEX両方を更新しなければいけないからです

SQL の INDEX は、テーブルの特定の列に対してB-Tree などの索引データを別途持たせる仕組みで、本の巻末索引と同じ発想です。WHERE 
で絞り込むクエリが O(N) から O(log N) になるので検索が高速化しますが、INDEX 自体もメンテが必要なので INSERT / UPDATE / DELETE 
が遅くなり、ディスク容量も増えるというトレードオフがあります。なので「よく検索される列だけに貼る」「使われてない INDEX 
は消す」のが定石です。


よく検索される列だけに貼るのが重要


  INDEX の正体はこういう「値 → 行」の辞書：

  name_index = {
      "user_1":     <行1>,
      "user_2":     <行2>,
      ...   
      "user_77777": <行77777>,
  }
