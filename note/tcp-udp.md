# TCP と UDP の違い — 30 秒模範解答

## 🎯 これを覚える（口頭そのまま使えるバージョン）

> TCP は **コネクション型**のプロトコルで、3way ハンドシェイクで接続を確立してから通信します。**シーケンス番号と ACK によって順序保証と再送が組み込まれている**ため信頼性が高く、HTTP や SSH などで使われます。
>
> 一方 UDP は **コネクションレス**で、ハンドシェイクなしで投げっぱなしに送る方式です。**順序保証も再送もない**代わりに、ヘッダが 8 バイトと軽く、オーバーヘッドが小さいので速い。DNS や動画ストリーミング、ゲームのようなリアルタイム性が大事な用途で使われます。
>
> ざっくり言うと、**信頼性が必要なら TCP、速さと軽さが必要なら UDP** という使い分けです。

→ 約 30 秒（声に出して 200〜220 文字／15〜20 秒で読み切れる量）。

## 構成の骨組み（暗記するならこれ）

3 つのブロックに分けて覚える：

| ブロック | 内容 | キーワード |
|---|---|---|
| ① TCP の定義 | コネクション型・3way・信頼性 | 「**接続してから話す、確実に届く**」 |
| ② UDP の定義 | コネクションレス・投げっぱなし・軽い | 「**投げっぱなし、速くて軽い**」 |
| ③ ユースケースで締め | TCP=HTTP/SSH、UDP=DNS/動画/ゲーム | 「**信頼性なら TCP、速さなら UDP**」 |

**「TCP は◯◯、UDP は△△、使い分けは□□」**の 3 部構成にすると、頭の中で組み立てやすい。

## 短縮版（15 秒）

> **TCP は接続を確立してから通信するコネクション型で、順序保証と再送がある信頼性重視のプロトコル**。**UDP は投げっぱなしのコネクションレスで、保証はない代わりに軽くて速い**。HTTP は TCP、DNS や動画ストリーミングは UDP、というのが代表的な使い分けです。

→ 約 100 文字。詰まった時の最低ライン。

## 入れると深く聞こえるキーワード

模範解答に**1〜2 個だけ**散らすと一気に「分かってる人」感が出る：

- **「3way ハンドシェイク」** — TCP の接続確立を具体的に言える
- **「シーケンス番号と ACK」** — 信頼性の中身を一言で説明できる
- **「ヘッダが 8 バイト」** — UDP の軽さに数値で裏付け
- **「HTTP/3 は QUIC（UDP ベース）」** — 知識が新しいことを示せる ⭐

例：「ちなみに HTTP も最新の HTTP/3 では QUIC という UDP ベースのプロトコルに移行していて、TCP の接続確立のオーバーヘッドを削る方向に進んでいます」

→ これを最後に足すと面接官に「お、こいつ分かってるな」感を出せる。

## NG パターン（避ける言い回し）

| ❌ | 理由 |
|---|---|
| 「TCP は信頼性、UDP は速さです」 | 短すぎる。30 秒の質問に 5 秒で答えるのは雑 |
| 「UDP は信頼性ゼロです」 | 厳密には**チェックサムはある**。「順序保証と再送がない」が正確 |
| 「UDP は速いから採用される」 | 因果が逆。「**保証が要らないので不要な処理を削れる→結果として速い**」 |
| 「Web は TCP です」 | HTTP/3 を考慮していないと突っ込まれる |
